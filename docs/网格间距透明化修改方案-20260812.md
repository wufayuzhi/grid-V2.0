# grid-V2.0 网格间距透明化 + 计算器预览 修改方案

> 状态：待用户确认后实施
> 日期：2026-08-12

## 一、背景 / 问题

1. **前端计算器显示错误**：`v3.html:3142` 网格 Tab 的"实际挂单间隔"用的是残留参数 `target_spacing_pct`（固定 0.6%），而引擎实际挂单用的是 `ATR% × 密度`（当前 3.1%）。**前端显示的和引擎执行的是两套公式，不同步。**
2. **黑盒问题**：前端计算器不显示 ATR%、实际波动、真实挂单价，用户调密度时看不到任何预览，无法判断"这个间距会不会成交"。
3. **保存不重挂**：`set_params`（保存参数接口）只存值不重挂，用户调完参数点确定后，现有挂单要等下一轮网格才更新。

## 二、最终定案（用户确认）

- **间距 = 用户人工设定的固定值**，系统不自动改。
- **ATR 时间框架 + 周期 + 密度滑块全部保留**，作为参考/可调参数，不删。
- **计算器全透明**：显示 ATR%、实际波动、实际间距、均价中轴、上/下挂单价。
- **ATR 只作参考显示**（算"实际波动"），不驱动间距。

## 三、修改内容

### 修改1：后端 `engine/grid.py` — 间距改为人工固定值
- 当前 `calc_grid_levels` L369-385：`atr>0` 时 `spacing = grid_spacing_pct(atr, anchor, density)`（ATR×密度）。
- 改为：**间距直接用人工设定值** `target_spacing_pct`（如 1.5%），不再用 ATR×密度。
- **保留「网格密度下限」保护（density_min）**：文档§1.2 定义 `密度下限 = max(滑块设定值, 2×实际费率 ÷ ATR%)`（滑块 0.3~1.0，默认 0.3）。作用：间距不能密到连手续费都覆盖不了——ATR 越小时，`2×费率÷ATR%` 越大，把密度下限抬升，保证间距价格能覆盖手续费。**此参数前端有滑块，保留不动，仍需在计算器里展示计算值。**
- 保留 bePx 双夹逼（L390-395）：上端≥多头bePx、下端≤空头bePx。

### 修改2：后端 `api/routes.py` `set_params` — 保存后立即重挂
- 保存参数后追加逻辑：
  - 重算挂单价（用新间距/新锚）
  - 与当前 `grid_upper_px/grid_lower_px` 比对
  - 不一致 → 撤当前4单 → 按新价重挂（`place_grid_orders`）
  - 一致 → 不动

### 修改3：后端 state/API — 返回计算链中间值（透明化）
- `/api/v1/state` 或计算器接口需返回：`atr_pct`（ATR%）、`grid_spacing_pct`（实际间距）、`grid_upper_px/lower_px`（真实挂单价）、`long/short avg_px`（中轴来源）。
- 确认这些字段已通过 `to_dict()` 暴露（部分已存在）。

### 修改4：前端 `v3.html` 网格 Tab 计算器 — 透明预览 + 滑块联动
- `updatePMResult('grid')`（L3141-3152）改为：
  - **删掉残留** `target_spacing_pct` 死值
  - 右侧显示：`ATR%`、`实际间距`、`实际波动`、`均价中轴`、`上方挂单价`、`下方挂单价`
  - 实际间距用后端返回的 `grid_spacing_pct`（或按新间距公式算）
  - 拖间距/密度滑块 → 实时刷新右侧预览
- 保留左侧所有滑块：ATR时间框架、ATR周期N、基础网格密度、间距。

### 修改5：删除残留参数
- 前端 `applyPreset` 预设（conservative/standard/aggressive）里的 `target_spacing_pct` 调整值，改为统一用 `target_spacing_pct`（间距）参数语义。

## 四、不改动

- ATR 公式本身（TR/avg_true_range）不动。
- 密度下限保护逻辑保留。
- bePx 成本保护保留。
- 建仓/止盈/失衡/风控等其它机制不动。

## 五、验证

1. 改完 `python3 -c "import models"` 验证无循环 import。
2. 前端 JS `node -e "new Function(code)"` 验证无语法错。
3. 实测：打开计算器网格 Tab → 确认右侧显示 ATR%、间距、上下挂单价 → 拖间距滑块 → 右侧实时变。
4. 保存参数 → 确认现有挂单按新间距撤单重挂。
5. 对比交易所 pending 挂单价 = 计算器显示的挂单价。
